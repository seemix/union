# Union v2 — аналіз, пропозиції та питання для обговорення

> Контекст: дві гілки одного репозиторію — `romana` (ro.baptist.org.md → WP `baptist.org.md/ro`) і `master` (ru.baptist.org.md → WP `baptist.org.md/ru`).
> Код на ~95% однаковий; відмінності — конфіг (URL, ID меню, ID категорій), тексти інтерфейсу, посилання у футері/віджетах, план читання Біблії і кілька фіч, які є лише в одній гілці.
> Мета: один застосунок на актуальному Next.js, який сам визначає, з якого WordPress брати дані.

### 1.2 Проблеми й технічний борг

**SEO / маршрутизація**
- Усі URL — query-параметри: `/post?id=…`, `/page?id=…`, `/category?id=…&page=…`. Немає slug-ів, canonical, sitemap, robots, hreflang, JSON-LD.
- Пагінація робиться через `router.push` (JS-кнопки) — пошуковики не бачать наступних сторінок.
- Посилання відносні (`'post?id='`, `'page?id='`) — ламаються на вкладених шляхах.
- Відсутній `notFound()` — неіснуючий `id` дає помилку/порожню сторінку з кодом 200 замість 404.

**Дані / продуктивність**
- `MyImage` робить `HEAD`-запит на **кожну** картинку під час SSR → кожна категорія = +8 мережевих запитів.
- Категорія — `cache: 'no-cache'`, пост — `revalidate: 10`, головна — 60: кеш хаотичний, WP навантажується зайве.
- Головна робить запити послідовно (`await` по черзі) замість `Promise.all`.
- `CategoryName` — окремий запит на назву категорії (у ru — двічі: в метаданих і в сторінці).
- Меню — єдине місце, де використовується WPGraphQL (зайвий плагін-залежність).
- Логіка excerpt продубльована в `category/mapper.ts` і `search/mapper.ts`.

**Безпека / надійність**
- `search`: `query` підставляється в URL без `encodeURIComponent`.
- `markText` будує `RegExp` з введення користувача без екранування → запит на кшталт `(` або `[` кладе сторінку; підсвітка також може розірвати HTML-теги/атрибути.
- Ендпойнт `custom/v1/view-post/{id}` — відкритий `POST` без жодних обмежень: накрутка лічильника будь-ким і будь-скільки.
- У вставленому PHP є синтаксичні помилки (`currentviews=(int)getpostmeta(post_id…` — без `$` і `_`). Ймовірно, артефакт копіювання, але варто перевірити, що саме зараз на сервері.

**Featured image «костиль»** — чому злітає
- Код лежить у `functions.php` теми. При оновленні теми (а не ядра WP) файл перезаписується — і `fimg_url` зникає.
- Додатково: розмір `app-thumb` реєструється темою (`add_image_size`). Якщо тему змінять — розміру не буде, навіть якщо код збережеться.

**Інше**
- `server.js` з мертвими маршрутами `/a`, `/b`; `.htaccess` від SPA; `cont.html`, `back/` — сміття в репо.
- `context.tsx` типізований як `any`; `alt` у картинок = URL картинки (погано для a11y/SEO).
- Next 14.2, React 18, `framer-motion` 11, ESLint 8 — все застаріле.
- Захардкожені рядки інтерфейсу (напр. «результаты поиска» російською в румунській версії).

## 2. Пропоновані рішення

### 2.1 Один застосунок, мульти-сайт за доменом (multi-tenant)

```
запит → proxy.ts (Next 16, колишній middleware)
        ├─ визначає сайт за Host: ru.baptist.org.md → "ru", ro.baptist.org.md → "ro"
        ├─ 301-редиректи старих URL (?id=…) → нові SEO-URL
        └─ rewrite → /[site]/... (внутрішньо, користувач цього не бачить)

src/
  app/[site]/            ← усі сторінки, site = "ru" | "ro"
  config/sites.ts        ← WP-URL, ID меню/категорій, футер, віджети, соцмережі, lang, title
  i18n/ru.ts, ro.ts      ← усі тексти інтерфейсу
  data/bible/ru.ts, ro.ts
  lib/wp/                ← типізований клієнт WP REST (fetch + теги кешу)
```

- Один білд, один процес обслуговує обидва домени; кеш розділений по `site` автоматично (бо це сегмент шляху).
- Для локальної розробки: `SITE_OVERRIDE=ro npm run dev` або `ro.localhost:3000`.
- Додати третю мову/сайт = додати запис у `sites.ts` + словник.

### 2.2 SEO-посилання з повною зворотною сумісністю

Нова схема (рекомендована):

| Тип | Старий URL | Новий URL |
|---|---|---|
| Пост | `/post?id=113186` | `/post/113186-slug-posta` |
| Сторінка | `/page?id=893` | `/page/istoria` |
| Категорія | `/category?id=23&page=2` | `/category/stiri-interne/2` (або `?page=2`) |
| Пошук | `/search?query=…&page=…` | `/search?q=…&page=…` (noindex) |

- `proxy.ts` ловить старі URL → бере slug із WP (`?_fields=slug`, кешується) → **301** на новий URL. Старі посилання з Facebook/месенджерів/Google працюють назавжди.
- Формат `id-slug`: пошук поста за id (швидко, 1 запит), slug — для людей і SEO; якщо slug змінили в WP — 301 на актуальний (canonical не ламається).
- Додати: `sitemap.ts` (з пагінацією по WP), `robots.ts`, `canonical`, Open Graph/Twitter, JSON-LD `NewsArticle`/`BreadcrumbList`, коректний `lang`, `hreflang` (лише головна, Q7).
- Пагінація — звичайні `<Link>`, а не `router.push`.

### 2.3 Featured images без «костиля»

Використати **стандартний** механізм WP REST — `_embed`:

```
GET /wp-json/wp/v2/posts?_embed=wp:featuredmedia,wp:term&_fields=id,slug,date,title,excerpt,views,_links,_embedded
```

```ts
const media = post._embedded?.['wp:featuredmedia']?.[0];
const img = media?.media_details?.sizes?.['app-thumb']?.source_url
         ?? media?.media_details?.sizes?.medium_large?.source_url
         ?? media?.source_url
         ?? FALLBACK_IMAGE;
```

Це ядро WordPress — не зламається від оновлень теми/ядра. `fimg_url` стає не потрібним узагалі. Fallback за розмірами захищає і від зникнення `app-thumb`.

### 2.4 Лічильник переглядів — надійно і без накруток

Запис у БД WP без серверного коду неможливий, тож PHP лишається, але:

1. **Перенести код з `functions.php` у must-use плагін** `wp-content/mu-plugins/baptist-headless.php`. MU-плагіни не перезаписуються ні оновленням ядра, ні оновленням теми, і їх не можна випадково вимкнути в адмінці.
2. ~~`register_post_meta('views')`~~ — не потрібно: `views` у REST віддає WP-PostViews (див. Q9).
3. Ендпойнт інкременту захистити секретом (заголовок `X-Union-Secret`, значення в `wp-config.php` і в `.env` Next).
4. Браузер шле `POST /api/views/{id}` на **Next** (route handler, `navigator.sendBeacon`), Next перевіряє rate-limit (IP+пост), відсіює ботів за User-Agent і вже серверно шле запит у WP із секретом. Секрет у браузер не потрапляє.
5. Там же в mu-плагіні — хук `save_post`/`transition_post_status` → `POST https://{site}/api/revalidate` (on-demand ревалідація: нова новина з'являється на сайті одразу, а кеш можна тримати довго).

Обрано: mu-плагін + проксі через Next (Q10). WP-PostViews лишається для читання `views`.

### 2.5 Оновлення стеку

- **Next.js 16** (App Router, Turbopack, `proxy.ts`, асинхронні `params/searchParams`, `use cache`/`cacheLife`/`cacheTag`), **React 19**, TypeScript strict.
- `framer-motion` → пакет **`motion`** (`motion/react`) — та сама бібліотека, нова назва. Обережні анімації: поява карток (`whileInView`, stagger), перехід між сторінками, підменю, кнопка «вгору»; з повагою до `prefers-reduced-motion`.
- Swiper 11+ (лишається, Q16), `yet-another-react-lightbox`, `react-icons` — оновити.
- ESLint 9 flat config (+ Prettier), `next lint` у Next 16 прибрано.
- `output: 'standalone'` замість кастомного `server.js`.
- `html-to-react` → `html-react-parser` (швидший, кращий контроль над `<img>` → `next/image`, `<a>` → `next/link` для внутрішніх посилань).
- Видалити `MyImage` HEAD-запити → fallback на клієнті через `onError`.
- `markText` — екранування regex, підсвітка лише в текстових вузлах (через парсер, а не регекспом по HTML).

### URL / SEO
- ✅ **Q3. Формат `/post/113186-slug`**, префікс `post` не змінюємо.
- ✅ **Q4. Кирилиця в ru-slug-ах — лишаємо кирилицю** (без транслітерації). У URL іде slug як є у WP; WP зберігає його percent-encoded, тому при порівнянні з URL обидві сторони нормалізуємо (`decodeURIComponent`), а в `Location`/canonical віддаємо закодований варіант. - ✅ **Q5. Старі посилання лише виду** `/post?id=…` (напр. `ro.baptist.org.md/post?id=16303`, `ru.baptist.org.md/post?id=113186`). Редиректи зі старих WP-URL (`?p=`, `/2023/05/…`) **не робимо**. Редиректи `/page?id=`, `/category?id=` лишаємо як дешеву страховку.
- ✅ **Q6. Сторінки — `/page/slug`** (безпечніше).
- ✅ **Q7. Зв'язку між мовами немає** → `hreflang` лише на головній (ru ⇄ ro).
